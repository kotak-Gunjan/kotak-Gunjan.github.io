Automated HTTPS for microservices on edge clusters

            
Traefik · Ingress · ACME / Let's Encrypt · Helm

          

          

            

              

                
PROBLEM / LEGACY STATE

                
Services were exposed through NodePort, which forces ports in the 30000+ range.
                  Users could not reach apps on standard 80/443, and TLS certificates were left to each application.

              

              

                
SOLUTION

                
Building on a colleague's proof of concept, I implemented it in the platform using the Traefik
                  ingress built into K3s with its native ACME resolver. The deployment library now generates the Ingress, the Traefik HelmChartConfig and a volume for
                  certificate storage only when an app asks for public HTTPS.

              

              

                
TOOLS & TRADE-OFFS

                
    
                  
  • Traefik ACME instead of cert-manager: fewer moving parts on low-resource edge nodes.
    • 
                  
  • HTTP-01 challenge needs the node to be publicly reachable on port 80.
    • 
                  
  • Conditional manifests keep internal-only apps free of extra components.
    • 
                

              

              

                
RESULT

                
Apps are served on 80/443 with automatically issued and renewed certificates,
                  with no manual certificate steps. Verified end to end with an industry partner's application on the project testbed.

Per-node cluster provisioning across cloud and edge

            
cluster-builder (co-developed, on PyPI) · OpenTofu · PostgreSQL · AWS · OpenStack

          

          

            

              

                
PROBLEM / LEGACY STATE

                
Provisioning lived in one monolithic class with a single shared state.
                  Adding or removing one node risked touching the whole cluster, and mixed providers caused duplicate provider blocks.

              

              

                
SOLUTION

                
Refactored to one OpenTofu workspace per node, rendered from templates.
                  State is stored in PostgreSQL, with a separate schema per cluster so clusters stay isolated.

              

              

                
TOOLS & TRADE-OFFS

                
    
                  
  • Per-node workspaces: safe single-node changes, at the cost of more state objects to manage.
    • 
                  
  • PostgreSQL backend: shared, lockable state without depending on a cloud bucket.
    • 
                  
  • OpenTofu version pinned for reproducible runs.
    • 
                

              

              

                
RESULT

                
Nodes can be added or removed one at a time across AWS, OpenStack and Raspberry Pi.
                  Provider duplication and edge node delete bugs were fixed, and AWS workers now wait for SSH before joining.

k3s-client: a safe deployment library for the Swarm Agent

            
Author & lead developer · Python · Kubernetes SDK · Pydantic

          

          

            

              

                
PROBLEM / LEGACY STATE

                
The agent drove the cluster by shelling out to kubectl. Errors were plain text,
                  dry runs were not real, and there was no clean way to pin workloads to specific edge devices.

              

              

                
SOLUTION

                
Rebuilt on the official Python SDK with server-side apply and distinct field managers,
                  real server-side dry runs, and node pinning using single-replica Deployments with hard node affinity.

              

              

                
TOOLS & TRADE-OFFS

                
    
                  
  • Single-caller (leader-only) design: simpler logic, no distributed locking needed.
    • 
                  
  • Default namespace only: smaller permission surface, less flexibility.
    • 
                  
  • Found injected service env vars breaking config validation; fixed with enableServiceLinks: false.
    • 
                

              

              

                
RESULT

                
Typed, testable cluster operations with real dry runs before every change.
                  Published on PyPI (pip install k3s-client) with versioned releases, unit tests and scripts for testing on real hardware.
